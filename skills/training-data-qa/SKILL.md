# 训练样本构造与标注质检

将治理数据变成可复现、可审计的数据集；未经专家确认的生成结果只能标为候选。

## 输入与启动

先阅读 [数据契约](references/contracts.md)，输入包括治理数据、任务模板、黄金样例、标注规则、业务约束和可选模型输出。可直接运行 [完整示例](assets/example/request.md)。缺项时列出具体字段；允许先做不依赖缺项的检查。没有规则、来源许可或事实依据时不能推定通过。

1. 明确任务、规模、标签、覆盖维度、四类集合用途与准入条件。区分目标规模与真实可用规模，不为凑数复制样本。
2. 核验治理数据的来源、使用授权、脱敏状态、证据版本。真实数据仅保存在授权位置；发布本 Skill 不代表允许发布业务样本。
3. 在生成之前按实体、文档、会话、事件或时间建立不可拆分来源组；有关联的组先求连通分量。同一来源及所有衍生、改写、翻译、难例必须继承集合。时间预测任务改用时间隔离并保留间隔。测试和独立评测不得用于提示优化、检索素材、扩增或规则调参。
4. 从来源证据构造种子，逐条记录字段级证据。黄金样例需要专家裁决，不能因与模型输出一致就成为黄金。冲突时保留证据和歧义，不擅自覆盖黄金标签。
5. 按缺口扩增训练集，记录父样本、生成器版本、提示词哈希、随机种子、变换类型。限制同一父样本及合成样本占比。难例覆盖近边界、易混标签、信息不足、反例与约束冲突；改变事实的反事实样本必须明确标记并走独立规则，不伪装成来源事实。
6. 根据 [检查与验收](references/quality.md) 运行机器质检，输出逐样本问题、统计与未覆盖项。修复后重跑；禁止静默丢弃坏行、自动删除冲突样本或将机器初筛称为事实正确率。
7. 按集合、标签、来源、生成类型及风险分层抽检，另加全部高风险样本；输出盲审任务，记录专家独立判断、分歧裁决与规则修订。抽检中发现系统性错误时扩大受影响层抽检或全检，规则变化后重标受影响样本。
8. 达到约定门槛才封存；不满足时交付候选集、阻断问题与补充任务。封存包括四类集合、任务、报告、问题样本、输入哈希、规则版本、生成参数、评审记录和来源链。已封存版本不可覆盖，修订创建新版本。

## 可执行工具

安装 `python3 -m pip install -r requirements.txt`（仓库根目录）。Skill 单独安装时安装 `jsonschema>=4.18,<5`。

```bash
python3 scripts/dataset_qa.py build --input assets/example --out /tmp/training-data-demo
python3 scripts/dataset_qa.py check --input assets/example --out /tmp/training-data-demo
python3 scripts/dataset_qa.py review --input assets/example --out /tmp/training-data-demo
# 专家填写 reviews.json 后才能封存；不得代签
python3 scripts/dataset_qa.py seal --input assets/example --out /tmp/training-data-demo --version v1
```

路径相对 Skill 目录。脚本是证据抽取型示例适配器：支持 JSONL、四类集合、精确重复、来源/谱系交叉检查、字符近似提示与标签分布检查。自定义任务需替换构造适配器及任务专用 Schema/规则；不得直接套用抽取示例生成分类或推理标签。大规模任务先读 [分片与标注编排](references/scaling.md)，使用磁盘索引、分桶候选检索和分批报告；当前工具把数据放入内存，近似扫描有上限，报告披露跳过项，不能宣称完成全量语义去重。

## 交付

汇报实际规模、各集合分布、合成比例、问题严重度、抽检完成度、泄漏检查覆盖范围与版本位置。报告中分开写“自动通过”“专家确认”“未检查”；版本封存代表符合已声明检查范围，不代表无未知偏差或无语义泄漏。
