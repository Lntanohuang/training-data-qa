# 大规模构造与标注编排

当目标为数十万至百万级样本时，先读取本文件，选择现有数据平台能力；不将演示脚本的内存扫描当作生产处理器。

## 作业与可恢复性

1. 冻结输入快照，为来源/业务实体建立持久ID。以关系边表求来源连通分量，登记 `component_id → split`；时间任务按事件时间与可见时间共同限制。超大连通组单独报告，不随机拆分。
2. 将任务按 `version/task_id/component_id/generation_recipe` 分片，生成幂等键；维护 queued/running/succeeded/failed/quarantined 状态。重试只补失败分片，结果按幂等键去重；记录请求ID、重试次数与模型版本。
3. 构造前输出配额表：集合×标签×来源×难度×真实/合成，各层当前规模、缺口、来源组数、最大单父样本数。隔离集缺口通过新独立来源补足；训练扩增不能填补隔离集。
4. 生成后先做逐行 Schema 和规则检查，坏行进入隔离表保留原始行号。再用数据库唯一索引检查ID/规范化内容哈希，用来源和父子关系表做跨集合连接检查。
5. 近似去重先按任务/语言/长度分桶，使用 MinHash/LSH 或向量近邻寻找候选；固定嵌入版本、阈值、索引参数。对跨集合候选优先专家核验，记录候选召回的抽样验证；没有命中不等于证明无泄漏。
6. 汇总分布并按来源/实体分组计算不确定性，防止把同一来源大量扩增当作独立样本。超出配额的合成样本降采样时保存选择清单和种子，不覆盖原始候选。

## 专家任务模板

每条任务至少保存：`task_id, sample_id, dataset_version, sample_hash, rule_version, stratum, risk, reviewer_role, assignment_status, blind_answer, decision, error_codes, evidence_refs, reviewer_id, reviewed_at, adjudicator_id, adjudication`。

开放题可先盲审作答，再展示候选标签以核对；避免在盲审界面泄露模型答案。双审分歧进入裁决队列，不能简单多数票掩盖规则歧义。按错误类型回流到标注规则、生成模板或治理数据；标记依赖并重跑受影响分片。

## 验收与版本

最终报告同时展示分片完成率、有效样本数、来源组数、各层覆盖、重复候选处置率、专家完成率、分歧率、残留错误与未运行检查。涉及模型训练历史的污染检查需要训练清单/外部基准及授权访问，没有输入时明确“无法核实”。

生产封存将数据写入新对象存储前缀并校验每个文件哈希，所有分片和评审完成后再写完成标志；设置访问控制、保留策略和防覆盖配置。快照清单包含工具链锁文件、数据许可与脱敏说明、集合分配表和评测访问记录。发布给外部仓库前只导出明确授权的数据；本 Skill 仓库只包含虚构示例。
